# Ploeg features by bounded context

What Ploeg does, grouped by the four bounded contexts of its [domain model](../domain/model.yaml) (Dispatch, Integration, Execution, Harness), in that model's words, with each context's ports and adapters as the Go code defines them. Ploeg names no consumer; any service that calls the operator API is an **Operator Consumer** here.
Checked against `development` at `9c70ae5`. Evidence links point at the files that implement or decide each feature.

## Context map

| Context | What words mean here | Upstream/downstream relations |
|---|---|---|
| **Dispatch** | The core: which Work Item runs, for which Team, in which Shift and Round, under which Lease and Hold, and when it is finished. Provider- and runtime-agnostic. | **Downstream of Integration through an Anti-Corruption Layer**: it sees only normalized Tracker Events and Forge Events, and compares a Scope for equality only (R7). **Supplier to Execution** (Customer-Supplier): Execution claims Runs and reports Outcomes through the Run API. **Conformist to the tracker** for priority (R10, Team Queue order). Talks to the knowledge graph (Omnigraph) as a **Conformist**: it calls only the stored queries the graph declares. |
| **Integration** | Everything vendor-specific: Tracker Providers, Forge Providers, Forges, webhooks, write-backs, and the Operator Consumers that ask Ploeg to admit work. | **Anti-Corruption Layer** in front of every tracker and forge: the Tracker port and Forge port (ADR-0183 proposed), implemented as `TrackerProvider` and `ForgeProvider` with optional capability interfaces. **Open Host Service + Published Language** toward Operator Consumers: the operator API with versioned JSON schemas, a served-contracts registry and consumer expectation files replayed in CI (consumer-driven contracts). ploeg-mcp is itself an Operator Consumer client of that host service. |
| **Execution** | How an admitted Run is performed: the Executor, the worker, the Inference Account and Push Credential minted per Run, Cost Status, verification and isolation. | **Customer of Dispatch** through the Run API (**Open Host Service**, Published Language `run-api.v1`; the Executor SPI is a prose contract any launcher may implement). **Anti-Corruption Layer** in front of the model gateway (`llmbroker`: "gateway-specific identity stays inside the implementation") and in front of forges for push rights (`forgebroker`). **Conformist** to Kubernetes, KEDA and agent-sandbox. |
| **Harness** | The agent-tool boundary: a Harness Adapter takes a Task Spec and returns an Outcome Report from one Agent Container. | **Published Language** (`taskspec.v1`, `outcomereport.v1`) between Execution and every Harness. Each Harness Adapter is an **Anti-Corruption Layer** over one Harness (Claude Code CLI, ACP agents, OpenHands, an arbitrary binary). ACP is an external standard the `acp` adapter **conforms** to. |

## Context: Dispatch

Dispatch decides what work runs and when it is finished. It mirrors a Tracker Item into a **Work Item**, routes it with **Routing Rules** to a Team and a **Work Target**, admits it (**Admission**), opens one **Shift** per Team engagement, runs the Shift's **Plan** as **Rounds** of Runs, grants a writing Run the Shift's **Lease**, keeps a **Hold** on budget until spend settles, and records each Run's **Outcome**. It owns the blackboard Runs are briefed from and the knowledge that reaches them by **Knowledge Scope**. It never sees a vendor payload and never orders work itself: the **Team Queue** mirrors the tracker. Words that mean only what they mean here: Shift, Round, Plan, Lease, Hold, Admission, Routing Rule, Follow-Up.

### Domain capabilities

#### Work Item, Outcome and Work Target

- **Work Item lifecycle** — A Work Item moves through `ingested`, `proposed`, `queued`, `active`, `needs_human`, `awaiting_review`, `stale`, `done` and `withdrawn`; `active` means a Team's Shift works it, whether or not a Lease is held (ADR-0093). — `shipped` — [pkg/work/types.go](../../pkg/work/types.go)
- **Work Item origin** — Each Work Item records whether it came from an Assignment, from other work as a Follow-Up (`follow_up`), or exists only in Ploeg (provider `ploeg`: manual-origin or Run-created). — `shipped` — [pkg/work/types.go](../../pkg/work/types.go)
- **Outcome** — A Run ends with one closed-set Outcome: `pr_opened`, `pr_updated`, `issue_updated`, `follow_up_created`, `stuck`, `failed`, `no_change_needed` or `yielded`; `stuck` must carry a reason (R4). — `shipped` — [pkg/work/types.go](../../pkg/work/types.go)
- **Recovery policy: infrastructure failure vs agent failure** — A failed Outcome carries a typed reason (`infra_node`, `infra_llm`, `agent_error`, `budget`, `lease_lost`, `timeout`, `idle`, `credential_leak`, `shared_budget_spent`); `IsInfra` and `ParksForHuman` decide which retry counter it uses or whether the Work Item waits for a person (R5; ADR-0021 proposed, code present). — `shipped` — [pkg/work/types.go](../../pkg/work/types.go)
- **Work Target on the Work Item** — The forge id, owner, repository and base branch are stored on the Work Item, never on the Team, with the Routing Rule and the hint that chose them (ADR-0014, R11). — `shipped` — [pkg/work/types.go](../../pkg/work/types.go)
- **Lease and Checkpoint records** — A Lease is a Team's crash-safe exclusive right to write the Shift's branch; a Checkpoint is a small durable progress record with phases such as `branch_created`, `briefed` and `prompt_started`. — `shipped` — [pkg/work/types.go](../../pkg/work/types.go), [pkg/work/board.go](../../pkg/work/board.go)
- **Shift branch and tracker reference** — Each Work Item gets a deterministic branch, a Follow-Up reuses its source branch, and the Tracker Item reference goes into commit trailers. — `shipped` — [pkg/work/branch.go](../../pkg/work/branch.go)
- **OpenSpec change named by a Work Item** — A description line can name an OpenSpec change; the id is parsed and bounded to 100 characters. — `shipped` — [pkg/work/openspec.go](../../pkg/work/openspec.go)

#### Intake: Routing Rules and Admission

- **Routing Rules and Teams from one configuration file** — `PLOEG_CONFIG` holds `trackers`, `targets` and `teams` in one YAML file, rendered by the chart as a ConfigMap; the older env forms (`PLOEG_TARGET_MAP`, `PLOEG_TEAM_MAP`, `PLOEG_TEAM_PLANS`) are still parsed when it is absent. — `opt-in config` — [pkg/config/config.go](../../pkg/config/config.go), [ops/helm/ploeg/templates/config.yaml](../../ops/helm/ploeg/templates/config.yaml)

- **Routing Rule: a Scope pins a Team** — A project's `team` sends all of that Scope's work to one Team and beats the assignee mapping (`ScopeTeams`, `pinTeam`). — `opt-in config` — [pkg/config/resolve.go](../../pkg/config/resolve.go), [pkg/config/config.go](../../pkg/config/config.go), [pkg/httpapi/server.go](../../pkg/httpapi/server.go)
- **Routing Rule: the assignee picks the Team** — `teams.<name>.assignees` lists the tracker usernames that hand work to a Team, so a person assigns a colleague rather than an infrastructure tier; merged with `PLOEG_TEAM_MAP`, configuration wins (ADR-0095 accepted). — `shipped` — [pkg/config/config.go](../../pkg/config/config.go), [cmd/ploegd/main.go](../../cmd/ploegd/main.go)
- **Routing Rule: one Ploeg user plus a Team label** — `trackers.<kind>.dispatchUser`, `teams.<name>.labels`, `labelRouting`; only GitHub Issues has label routing today. — `proposed (ADR-0095)` — [docs/adrs/0095-work-is-handed-to-ploeg-by-assigning-one-ploeg-user-and-a-team-label-picks-the-team.md](../../docs/adrs/0095-work-is-handed-to-ploeg-by-assigning-one-ploeg-user-and-a-team-label-picks-the-team.md), [pkg/config/config.go](../../pkg/config/config.go)
- **Route refusal** — A Tracker Item that no Routing Rule covers is not queued; Ploeg audits it, comments on the Tracker Item how to fix it, keeps the newest refusal per item and lists refusals with the reason and the allowed Work Targets (ADR-0038). — `shipped` — [pkg/httpapi/server.go](../../pkg/httpapi/server.go), [pkg/store/store.go](../../pkg/store/store.go), [pkg/store/route_refusals.go](../../pkg/store/route_refusals.go), [pkg/httpapi/operator.go](../../pkg/httpapi/operator.go)
- **Work Target readiness** — Archived repositories, mirrors and repositories without `AGENTS.md` on the base branch are not ready; checked at load, at ingest and at claim. — `shipped` — [pkg/target/readiness.go](../../pkg/target/readiness.go)
- **Admission of a manual-origin Work Item** — An Operator Consumer's request records a queued Work Item with its Work Target, an optional budget and an optional Harness and Model per Role; a replay with the same request id returns the admitted Work Item and starts nothing (R20; ADR-0102, ADR-0098, ADR-0103 accepted; OpenSpec `submit-work-items` 19/19). — `shipped` — [pkg/store/operator_work_admission.go](../../pkg/store/operator_work_admission.go), [pkg/httpapi/operator_work_admission.go](../../pkg/httpapi/operator_work_admission.go), [pkg/httpapi/admission_selection.go](../../pkg/httpapi/admission_selection.go), [openspec/changes/submit-work-items/tasks.md](../../openspec/changes/submit-work-items/tasks.md)
- **Dispatch waits on tracker dependencies** — A Work Item whose Tracker Item has open blockers gets no Shift; the tracker is re-read every 5 minutes (`PLOEG_DEPENDENCY_HOLD`, `PLOEG_DEPENDENCY_RECHECK`) (ADR-0123 accepted). — `shipped` (default on) — [pkg/shiftengine/dispatch_gate.go](../../pkg/shiftengine/dispatch_gate.go), [pkg/store/dependencies.go](../../pkg/store/dependencies.go), [cmd/ploegd/main.go](../../cmd/ploegd/main.go), [pkg/config/config.go](../../pkg/config/config.go)
- **Premise check before a writer** — One classifier call says whether a Work Item can go to a writer (`proceed`), needs a person's answer first (`ask`) or is too big for one pull request (`too_big`); it runs on the sweep path only, within a per-sweep allowance, and `ask`/`too_big` parks the item and tells the Tracker Item why; a Team turns it on with `premiseCheck.model` (ADR-0123 accepted, deciding ADR-0036's T0). — `opt-in config` — [pkg/premise/premise.go](../../pkg/premise/premise.go), [pkg/shiftengine/dispatch_gate.go](../../pkg/shiftengine/dispatch_gate.go), [pkg/store/premise.go](../../pkg/store/premise.go), [pkg/config/config.go](../../pkg/config/config.go)

- **Premise check frames tracker text as data** — Tracker text is framed as untrusted data and the reply is parsed strictly as one JSON object. — `opt-in config` — [pkg/premise/premise.go](../../pkg/premise/premise.go)
- **Withdrawal** — Unassigning or closing the Tracker Item withdraws un-started work and settles stopped work; a guarded withdraw runs by command id; `needs_human` and stopped Work Items are re-read from the tracker every 15 minutes and a closed one is withdrawn. — `shipped` — [pkg/httpapi/withdraw.go](../../pkg/httpapi/withdraw.go), [pkg/store/withdraw.go](../../pkg/store/withdraw.go), [pkg/shiftengine/engine.go](../../pkg/shiftengine/engine.go)
- **Stop a Work Item** — A person withdraws a Work Item, cancels its pending Runs and stops its running ones. — `shipped` — [pkg/httpapi/operator.go](../../pkg/httpapi/operator.go), [pkg/httpapi/withdraw.go](../../pkg/httpapi/withdraw.go)

#### Teams, Plans and Shifts

- **Team concurrency cap** — `maxRunning` (`PLOEG_TEAM_MAX_RUNNING`) is enforced inside the claim transaction under a per-Team advisory lock (`ClaimRoleWithin`); a claim over the cap is answered like an empty Team Queue. — `opt-in config` — [pkg/config/config.go](../../pkg/config/config.go), [pkg/store/team_capacity.go](../../pkg/store/team_capacity.go), [pkg/store/shift.go](../../pkg/store/shift.go)
- **Team spend cap** — `spendCap {usd, period}` per UTC day, week (from Monday) or month; a claim whose Hold would push the period's settled plus held spend over the cap starts nothing; `PLOEG_TEAM_SPEND_CAPS`; the chart default is `executor.spendCap: {usd: 20, period: day}` (ADR-0162 proposed, code present). — `shipped` (chart default) / `opt-in config` — [pkg/spendcap/spendcap.go](../../pkg/spendcap/spendcap.go), [pkg/store/team_spend_cap.go](../../pkg/store/team_spend_cap.go), [ops/helm/ploeg/values.yaml](../../ops/helm/ploeg/values.yaml)
- **Plan** — `plan.pool` (the Shift budget) and ordered `rounds` of `roles` with `name`, `writes`, `cap`, `planner` and `shadow`, plus `maxFixRounds` and `independentReview{model,harness}`; validated at boot, and each Run records the Plan's hash. — `opt-in config` — [pkg/plan/plan.go](../../pkg/plan/plan.go), [pkg/plan/independent_review.go](../../pkg/plan/independent_review.go)
- **Single-writer Plan for a Team without one** — `PLOEG_SHIFTS_UNIFORM` synthesizes one unnamed writing Role in one Round with an unmetered pool, so every Work Item has a Shift. — `shipped` (default true) — [pkg/shiftengine/engine.go](../../pkg/shiftengine/engine.go)
- **Role Model selection** — A Role's policy lists the Models it may use and a default; the Run stores one selected Model and an Admission may choose among the listed ones (ADR-0103 accepted). — `shipped` — [pkg/store/run_selection.go](../../pkg/store/run_selection.go), [pkg/store/shift.go](../../pkg/store/shift.go)
- **One rule set on two paths** — The same idempotent rules run on the fast path (ingest, Outcome report) and on the sweeper tick (`EvaluateAll`), so a crashed request handler never strands a Shift. — `shipped` — [pkg/shiftengine/engine.go](../../pkg/shiftengine/engine.go)
- **Shift opening** — At most one live Shift per queued Work Item (unique index), and its first Round starts (`EnsureShift`). — `shipped` — [pkg/shiftengine/engine.go](../../pkg/shiftengine/engine.go), [pkg/store/shift.go](../../pkg/store/shift.go)
- **Round advancement** — A Round advances only when every Run in it has finished; the next Round comes from the Plan, a stuck Run freezes the Plan and an exhausted Plan closes the Shift; derived from Run state, never from what an agent reports. — `shipped` — [pkg/shiftengine/engine.go](../../pkg/shiftengine/engine.go)
- **Fix Rounds driven by a Verdict** — A reading Run's `request_changes` reopens the writing Round as a fix Round, bounded by `maxFixRounds` and by the remaining pool with a 0.05 USD floor (ADR-0017 proposed, code present). — `shipped` (when a Plan has a reader) — [pkg/shiftengine/reviewloop.go](../../pkg/shiftengine/reviewloop.go)
- **Shift close reason** — Each close records why: `plan_exhausted`, `review_approved`, `fix_round_cap_reached`, `budget_exhausted_before_fix_round`, `budget exhausted`, `review_failed`, `budget held by unsettled runs`, `checks_not_passed`, `ci_not_finished`, `ci_not_passed`, `taken_over`. — `shipped` — [pkg/shiftengine/reviewloop.go](../../pkg/shiftengine/reviewloop.go)
- **State a closed Shift settles to** — A configured Plan that closes with a pull request moves the Work Item to `awaiting_review`, any other close parks it at `needs_human`; a synthesized Plan takes the state its Outcome implies. — `shipped` — [pkg/shiftengine/engine.go](../../pkg/shiftengine/engine.go)
- **A failed writing Run reopens its Round** — Retried within the agent and infrastructure attempt budgets, with a per-Role cap recovered from the Plan (ADR-0019 proposed, code present). — `shipped` — [pkg/shiftengine/failedwriter.go](../../pkg/shiftengine/failedwriter.go)
- **A failed reading Run is retried; a missing review closes `review_failed`** — (ADR-0043 accepted). — `shipped` — [pkg/shiftengine/failedreader.go](../../pkg/shiftengine/failedreader.go)
- **Infrastructure failure cap** — At most 10 consecutive infrastructure failures, counted apart from agent failures. — `shipped` — [pkg/store/store.go](../../pkg/store/store.go), [pkg/store/shift.go](../../pkg/store/shift.go)
- **A pool under a Hold waits for settlement** — When unsettled Runs hold a Shift's pool, the Shift waits for their spend to settle before it parks (ADR-0048 accepted). — `shipped` — [pkg/shiftengine/reviewloop.go](../../pkg/shiftengine/reviewloop.go)
- **A spent shared gateway budget parks the Work Item** — If a gateway budget wider than the Run's own key (gateway team or user) is spent, the Work Item parks instead of retrying (ADR-0111 accepted). — `shipped` — [pkg/shiftengine/budgetspent.go](../../pkg/shiftengine/budgetspent.go), [pkg/worker/budgetspent.go](../../pkg/worker/budgetspent.go), [pkg/litellm/errors.go](../../pkg/litellm/errors.go)

- **Claim by Harness** — Each allowed (Team, Role, Harness) has its own workload and a claim selects on its Harness; pending counts are reported per Harness for the scaler (ADR-0098, ADR-0099 accepted). — `shipped` — [pkg/store/shift.go](../../pkg/store/shift.go), [pkg/store/run_selection.go](../../pkg/store/run_selection.go)

## Context: Integration

Integration is the boundary to everything Ploeg does not own. A **Tracker Provider** turns a tracker webhook into a normalized **Tracker Event** carrying an opaque **Scope**, mirrors a **Tracker Item** and writes comments and status back; a **Forge Provider** does the same for a **Forge** with **Forge Events** and pull request comments. Each Tracker Provider implements the Tracker port and each Forge Provider the Forge port (ADR-0183 proposed), and declares what else its system can do by implementing optional capability interfaces. On the other side stands the **Operator Consumer**: a named service identity with Team scope that asks Ploeg to admit work, reads what happened, opens an **Ask** or a **Chat** against an **Ask Allowance** or **Chat Allowance**, and requests a **Publication Operation**. Words that mean only what they mean here: Scope, Tracker Event, Forge Event, Forge, Operator Consumer.

## Context: Execution

Execution performs admitted Runs. An **Executor** starts a process that claims one **Run** through the Run API; for a writing Run the worker receives a **Push Credential** bound to the Lease and an **Inference Account** whose per-Run model key is capped at what the Run was authorized. The worker clones the Work Target, briefs the Harness, runs it in isolation, reads the delivered result from the forge rather than from the agent, verifies it, reports the Outcome, and revokes every credential on every return path. Cost is always reported with a **Cost Status**. Words that mean only what they mean here: Run, Executor, Inference Account, Push Credential, Cost Status, Verification Receipt.

### Domain capabilities

#### Run orchestration in the worker

- **Run orchestration** — Claim → resolve the Work Target → clone → scan → brief → mint credentials → run the Harness → read the Outcome from the forge → verify → report; the worker owns Lease renewal, git identity, credentials and the ground truth about the Outcome. — `shipped` — [pkg/worker/worker.go](../../pkg/worker/worker.go)
- **Work Target resolution** — The worker uses the claimed Work Target and falls back to its env repository only when the Work Item resolved none, never blending the two; `PLOEG_TARGET_SOURCE=env` pins the fallback. — `shipped` — [pkg/worker/target.go](../../pkg/worker/target.go)
- **Worker boot validation** — Fails before claiming on a bad `LITELLM_KEY_BUDGET`, a missing forge credential, bad Harness or ACP arguments, toolchains, telemetry, plugins or verify commands; reports SIGTERM or eviction as an Outcome and revokes credentials. — `shipped` — [cmd/ploeg-worker/main.go](../../cmd/ploeg-worker/main.go)
- **Fail an unstartable Run** — When the Harness binary is missing, the worker claims a Run and fails it with the reason, so it does not loop. — `shipped` — [pkg/worker/unstarted.go](../../pkg/worker/unstarted.go), [pkg/worker/adapters.go](../../pkg/worker/adapters.go)

#### Authority and Run identity

- **Worker authentication** — `managed` (a bootstrap capability exchanged at claim for a signed Run capability, default), `legacy` (static, refused under P1), and an HMAC capability that turns off once transaction tokens are on; chart `executor.workerAuth` (mode, `hmacCapability`, signing and bootstrap secrets, `additionalLLMPolicies`). — `shipped` — [pkg/httpapi/worker_auth.go](../../pkg/httpapi/worker_auth.go), [cmd/ploegd/transaction_token.go](../../cmd/ploegd/transaction_token.go), [ops/helm/ploeg/templates/_worker_control.tpl](../../ops/helm/ploeg/templates/_worker_control.tpl), [ops/helm/ploeg/values.yaml](../../ops/helm/ploeg/values.yaml)

- **Client-carried Run** — A Run stored with carrier `client` that no worker claims; the person it acts for claims it through their Operator Consumer and runs it on their own Claude login (ADR-0112 proposed, code present). — `shipped` — [pkg/store/client_carried.go](../../pkg/store/client_carried.go), [pkg/httpapi/client_carried.go](../../pkg/httpapi/client_carried.go)

## Context: Harness

Harness is the fast-churning boundary to agent tools. A **Harness Adapter** makes one **Harness** (Claude Code CLI, an ACP agent, OpenHands, any binary) accept a **Task Spec** and write an **Outcome Report** from inside an **Agent Container**. Ploeg composes the prompt, the delivery contract and the agent-facing files; the adapter only drives the tool. A reading Run's **Verdict**, findings, questions, created Work Items and learnings travel back in the Outcome Report. The **Model** is reached only through the gateway wiring the worker provides. Words that mean only what they mean here: Harness, Harness Adapter, Agent Container, Task Spec, Outcome Report, Verdict.

### Domain capabilities

#### The contract: Task Spec in, Outcome Report out

- **Task Spec and Outcome Report** — Versioned JSON contracts between Ploeg and any Harness, published as schemas: the Task Spec carries the Work Item, repository, branch, trace id and OpenSpec brief and never a credential (R8); the Outcome Report carries the Outcome, optional created Work Items and worker verification. — `shipped` — [pkg/harness/contract.go](../../pkg/harness/contract.go), [docs/contracts/taskspec.v1.schema.json](../../docs/contracts/taskspec.v1.schema.json), [docs/contracts/outcomereport.v1.schema.json](../../docs/contracts/outcomereport.v1.schema.json)
- **Outcome drop box** — The agent writes its report to `$PLOEG_OUTCOME_FILE`, every Harness's return path, merged with what the adapter parsed (ADR-0018 proposed, code present). — `shipped` — [pkg/harness/dropbox.go](../../pkg/harness/dropbox.go)
- **Problem and solution account** — A writer reports the problem and the solution for a reader (ADR-0042 proposed, code present). — `shipped` — [pkg/harness/contract.go](../../pkg/harness/contract.go)
- **Verdict** — A reading Run returns `approve` or `request_changes`. — `shipped` — [pkg/harness/contract.go](../../pkg/harness/contract.go)
- **Findings and questions** — Findings have ids (`f<run>-<n>`) and a severity (`blocking`, `should_fix`, `nit`); a writer answers each with `fixed`, `disagree`, `out_of_scope` or `deferred`; questions go to a `person`, the `reviewer` or the `next_run` with ids `q<run>-<n>`; Ploeg validates and sanitises them (ADR-0121 accepted). — `shipped` — [pkg/harness/blackboard.go](../../pkg/harness/blackboard.go), [pkg/findings/findings.go](../../pkg/findings/findings.go)
- **Created Work Items in the Outcome Report** — A Run may propose Work Items within shape bounds. — `shipped` — [pkg/harness/contract.go](../../pkg/harness/contract.go)
- **Learnings** — A Run may propose up to 10 learnings for a person to review (ADR-0066 proposed, code present). — `opt-in config` (`PLOEG_KNOWLEDGE_OUTBOX`) — [pkg/harness/contract.go](../../pkg/harness/contract.go), [pkg/worker/knowledge.go](../../pkg/worker/knowledge.go)
- **Usage per Model** — Tokens, cost and turns per Model; a nil field means the Harness did not say (ADR-0045 proposed, code present). — `shipped` — [pkg/harness/contract.go](../../pkg/harness/contract.go)
- **Delivery binding** — ploegd refuses a reported delivery whose forge, repository or branch does not match the Run. — `shipped` — [pkg/harness/delivery.go](../../pkg/harness/delivery.go)
- **Verification record** — Checks are `passed`, `failed`, `incomplete` or `not_run`, and `HoldsBackReview` reads the result. — `shipped` — [pkg/harness/verification.go](../../pkg/harness/verification.go)
- **Spawn-and-wait base** — `RunCommand` lifts a command-shaped adapter: stdout captured up to 1 MiB, a tail buffer, an idle watchdog (`ErrIdle`), and the whole process group killed. — `shipped` — [pkg/harness/adapter.go](../../pkg/harness/adapter.go), [pkg/harness/procgroup_unix.go](../../pkg/harness/procgroup_unix.go), [pkg/harness/spawner.go](../../pkg/harness/spawner.go)

### Collisions the model does not resolve (proposals; the model is not edited)

1. **Lease** means the branch-write right in the model and a generic processing lease in the store (webhook inbox, comment slots, review watch, notes outbox). Proposal: keep Lease for the branch only; name the others "processing lease" in the Shared kernel and never in domain text.
2. **Board** means the tracker's board and the Run's blackboard (`pkg/boardview`, `$PLOEG_BOARD_FILE`, `/runs/{token}/board`). Proposal: add **Blackboard** to Dispatch; reserve "board" for the tracker, and rename the file and route on the next breaking contract major.
3. **Delivery** has six meanings in Ploeg (Delivery Candidate, delivery contract, delivery assertions, delivery facts, delivery gates, webhook delivery). Proposal: keep Delivery Candidate; say "delivery contract" only in Harness; rename "delivery claims" to **Delivery Assertion**; "delivery facts" to **Pull Request Facts**; a webhook delivery to **Webhook Delivery**.
4. **Gate** names a board status mapped to a delivery stage, the forge CI wait, the dependency/premise dispatch wait, target readiness and three repository CI gates. Proposal: Gate = a board workflow point (Integration); call the forge CI wait **CI Readiness**, the dispatch wait **Dispatch Wait**, and keep repository gates in the Shared kernel.
5. **Verdict / Ask** — the premise check returns a "verdict" of `ask`, colliding with both Verdict (a reader's answer) and Ask (a read-only Run). Proposal: **Premise Result** with values `proceed`, `needs_answer`, `too_big`.
6. **Scope** names the opaque tracker container, a Knowledge Scope, an Operator Consumer's Team scope and OAuth scopes. Proposal: Scope stays the tracker container; always write "Knowledge Scope", "Team scope" and "OAuth scope" in full.
7. **Team** also names a LiteLLM gateway team (`litellmTeamId`, "team budget" in gateway refusals). Proposal: write "gateway team" for the LiteLLM object; it is not a Ploeg Team.
8. **Session** is avoided for Shift but used for a Claude environment session, an ACP session, an MCP protocol session and the Operator Execution's linked session (`SessionID`). Proposal: qualify every use (Claude environment session, ACP session, MCP session, consumer session); never bare.
9. **Note** covers knowledge (Work Item Note), an instruction to the next Run (operator note) and a stop note. Proposal: add **Operator Note** as a separate Dispatch term; a stop note is a Work Item Note authored by Ploeg.
10. **Forge Event** — the model lists three kinds; the code normalizes seven (`pr_opened`, `pr_synchronized`, `pr_merged`, `pr_closed` as well). Proposal: extend the term's definition to the seven kinds.
11. **Port shape** — Execution reads delivered pull requests through direct GitHub, Forgejo and GitLab REST calls (pkg/worker/forge.go), and the premise check talks to LiteLLM through `premise.Gateway` instead of `llmbroker`. Both bypass the Integration and model-gateway seams R7 asks for. Proposal: route both through Forge port capabilities (ADR-0183 step 8 proposes `WorkerProfile`) and the gateway contract of ADR-0177.
12. **Capability** names an optional Tracker port or Forge port interface (ADR-0183), the bootstrap and Run capabilities of worker authentication, Linux capabilities the worker sheds, and a Harness Adapter's declared abilities (`Yielder`, `PromptLimiter`). Proposal: write "port capability", "Run capability" and "Harness Adapter capability" in full; Linux capabilities stay in code names (`CAP_SYS_PTRACE`).
13. **Status mapping** runs both ways: delivery gates map a tracker's statuses to development, test, acceptance and done (ADR-0051, read side), and the Status Mapping maps `awaiting_review`, `needs_human` and `done` to a tracker's statuses (ADR-0183, write side). ADR-0185 moves a Tracker Item through "the status mapping the operator configured for that board" and cites ADR-0051, so which side it means is open. Proposal: keep Delivery Gate for the read side and Status Mapping for the write side, and have ADR-0185 name the write side.
